### [Bug Fix] Preview API changes saved before classification showed as High

- **Files:** `backend/src/analysis/reclassify.js`, `backend/src/cli.js`, `backend/package.json`, `backend/test/reclassify.test.js`, `docs/architecture/api-surface.md`, `docs/SETUP.md`, `README.md`
- **Why:** the beta rollout of 16.0.20606.15070 (first seen 2026-10-14) was recorded before changes got an API status, so its rows kept the raw diff's severity: removals of preview APIs such as `Excel.SensitivityLabelAbacAttribute` were High instead of Low.
- **What:** `reclassifyStored` classifies stored changes without `apiStatus` from the `@types` catalogue and lowers their rollouts' severity to match (never raises it). `cli start` runs it at boot; `npm run reclassify -w backend` runs it alone. Idempotent.

### [Bug Fix] Overlapping crawls created duplicate rollouts

- **Files:** `backend/src/cli.js`, `backend/src/db.js`, `backend/test/lock.test.js`, `docs/architecture/README.md`, `docs/architecture/data.md`, `docs/SETUP.md`
- **Why:** on 2026-10-14 two processes crawled prod on the same database 25 s apart (21:29:35 and 21:30:00 UTC). Neither saw the other's new rollouts, so `onenote-winrt-16.00.js`, `visio-win32-16.00.js`, `word-ios-16.00.js` and `word-win32-16.01.js` each got two rollouts of the same sha; one completed, the other sat at 0% and was abandoned 24 h later. The `running` flag only guards one process.
- **What:** a crawl lock in MongoDB (`locks`, `_id: "crawl"`): `acquireLock` is an atomic `findOneAndUpdate` with `expiresAt` (15 min), renewed before each channel, released after the crawl and on SIGTERM/SIGINT; a process that cannot take it skips the tick. Backstop: a unique index on `{channel, region, path, toSha}` among `rolling` rollouts. SETUP: the production `MONGODB_URI` stays out of local `.env`; read-only MongoDB user for analysis scripts.
