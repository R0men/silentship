### [Feature] Umami events: open_rollout, view_rollouts, subscribe_start

- **Files:** `frontend/lib/analytics.js`, `frontend/components/Rollouts.js`, `frontend/components/Headline.js`, `frontend/components/Subscribe.js`, `frontend/app/privacy/page.js`, `frontend/lib/site.js`, `docs/architecture/analytics.md`, `docs/VERIFY.md`
- **Why:** visits and `subscribe` alone do not show where people drop off between landing, the rollout list and the sign-up form.
- **What:**
  - `open_rollout` (`channel`, `severity`, `from`: `list` | `headline`) on a click on a rollout row or the headline link; `view_rollouts` when the rollout list enters the viewport (`IntersectionObserver`), once per visit; `subscribe_start` on the first focus in the email field, once per visit.
  - `track` waits up to 10 s for the Umami script (it loads `afterInteractive`); `trackOnce` keeps a `sessionStorage` flag. `subscribe` goes through `track` too.
  - `/privacy` mentions the anonymous interactions; "Last updated" 2026-10-17.

### [Feature] API type pages (/reference)

- **Files:** `backend/src/web/queries.js`, `backend/src/web/server.js`, `backend/src/db.js`, `backend/src/analysis/api-catalog.js`, `backend/test/queries.test.js`, `frontend/app/reference/page.js`, `frontend/app/reference/[type]/page.js`, `frontend/lib/apiType.js`, `frontend/components/RolloutView.js`, `frontend/app/layout.js`, `frontend/app/sitemap.js`, `frontend/app/llms.txt/route.js`, `frontend/app/globals.css`, `docs/architecture/{seo,web,frontend,data,api-surface,README}.md`, `docs/VERIFY.md`, `docs/tasks/PLAN.md`
- **Why:** every changed API is an exact search ("Excel.SensitivityLabelAbacAttribute removed") the site could answer, but changes were only listed inside rollout pages.
- **What:**
  - One page per API **type** that changed in a confirmed rollout (`apiTypeOf`: up to the last PascalCase segment; no such segment → the parent object, e.g. `Office.context.ui`); members are anchors. Other types — 404, not in the sitemap.
  - Exact identifier as the URL; other spellings answer 308. A rename shows on the pages of both names (new index `apiChanges.{from}`).
  - Page: title and h1 say what happened and where ("… removed in Office.js beta (preview API)"); a rename names the page before a removal or addition; API status next to the name ("Preview · ExcelApi BETA", "GA · ExcelApi 1.19", "Undocumented") with a direct Microsoft Learn link or "Not in Microsoft's documentation"; state per channel; advice that depends on the status; the TypeError messages a removal causes (Chromium, and Safari when Mac/iOS changed); change history with hosts and rollout links; related types; JSON-LD `TechArticle` + `BreadcrumbList`.
  - Hub `/reference` by namespace; "API changes" in the nav; API rows on rollout pages link to their type; sitemap and `llms.txt` list the types.
  - Backend: `GET /api/types`, `GET /api/types/:type`; `/api/sitemap` returns types too.

### [Bug Fix] Preview API changes saved before classification showed as High

- **Files:** `backend/src/analysis/reclassify.js`, `backend/src/cli.js`, `backend/package.json`, `backend/test/reclassify.test.js`, `docs/architecture/api-surface.md`, `docs/SETUP.md`, `README.md`
- **Why:** the beta rollout of 16.0.20606.15070 (first seen 2026-10-14) was recorded before changes got an API status, so its rows kept the raw diff's severity: removals of preview APIs such as `Excel.SensitivityLabelAbacAttribute` were High instead of Low.
- **What:** `reclassifyStored` classifies stored changes without `apiStatus` from the `@types` catalogue and lowers their rollouts' severity to match (never raises it). `cli start` runs it at boot; `npm run reclassify -w backend` runs it alone. Idempotent.
