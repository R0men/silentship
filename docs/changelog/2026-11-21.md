### [Bug Fix] Microsoft's docs went back to appsforoffice: texts no longer call OneCDN recommended

- **Files:** `backend/src/crawler/loader.js`, `backend/src/notify/alerts.js`, `backend/src/web/queries.js`, `backend/src/config.js`, `frontend/app/rollouts/[channel]/[group]/page.js`, `frontend/lib/format.js`, `frontend/components/ChannelStatus.js`, `frontend/app/layout.js`, `frontend/app/page.js`, `frontend/app/llms.txt/route.js`, `frontend/content/notes/new-office-js-cdn-endpoint.md`, `backend/test/loader.test.js`, `backend/test/card-and-severity.test.js`, `README.md`, `TECH.md`, `docs/architecture/cdn-facts.md`, `docs/architecture/crawler.md`, `docs/architecture/frontend.md`
- **Why:** on 2026-11-19 Microsoft restored `appsforoffice.microsoft.com` in all its docs and removed the OneCDN endpoint and the migration steps (OfficeDev/office-js-docs-pr#5930). The site, README and `llms.txt` still called OneCDN recommended and `appsforoffice` legacy, and the loader-flags notice in emails, Slack and on release pages pointed to "Microsoft's migration notes" that no longer exist. The endpoint itself did not change: on 16.0.20710.15050 its host files are byte-identical and its `office.js` still differs by the two security-default lines.
- **What:** the loader-flags notice links our endpoints note instead (`flagsChangeNotice(…, publicUrl)`; the release page links it itself). The site labels the endpoint "appsforoffice" instead of "legacy" (the `legacy` key in data stays). The endpoints note has an update on the revert and is rechecked on 16.0.20710.15050. Docs describe the September–November recommendation as history.

### [Feature] Notes show when they were updated

- **Files:** `frontend/app/notes/[slug]/page.js`, `frontend/app/notes/page.js`, `docs/architecture/frontend.md`
- **Why:** a note's `updated` date reached only the metadata, so readers could not see that a note had changed.
- **What:** the note header and the `/notes` list show "· updated <date>" when `updated` differs from `date`.

### [Feature] SEO: one page per build, indexed API pages only where documented

- **Files:** `backend/src/web/queries.js`, `backend/src/web/server.js`, `frontend/app/rollouts/[channel]/[group]/page.js`, `frontend/app/reference/[type]/page.js`, `frontend/app/sitemap.js`, `frontend/lib/apiType.js`, `backend/test/releases.test.js`, `backend/test/api-type-text.test.js`
- **Why:** production and beta pages of the same build with the same API changes competed for the same searches (16.0.20619, 16.0.20626), and 23 of 40 indexed API type pages were undocumented internals few people search for.
- **What:** `getRelease("beta", …)` returns `canonicalTrack: "prod"` when production has the build with exactly the same API changes; the beta page's canonical points at production, it links there, and the sitemap lists production only. Undocumented types (`indexedType`) are `noindex, follow` and out of the sitemap; `/api/sitemap` sends each type's `docs` status.

### [Bug Fix] SEO: titles and descriptions fit search results

- **Files:** `frontend/lib/site.js`, `frontend/lib/apiType.js`, `frontend/lib/format.js`, `backend/src/web/queries.js`, `frontend/app/page.js`, `frontend/app/reference/page.js`, `frontend/app/rollouts/[channel]/[group]/page.js`, `frontend/app/sitemap.js`, `frontend/content/notes/*.md`, `backend/test/card-and-severity.test.js`
- **Why:** API type descriptions were 255–493 characters and titles up to 160; the home description was 201; the `/reference` description read "Office.ribbon: 1 RibbonApi 1.1 with a changed implementation"; rollout descriptions said "in 21 files … across 22 files"; the sitemap dated `/notes` by the newest `date`, not `updated`.
- **What:** type titles imply production and say only "beta", "(preview)", "(undocumented)"; `metaDescription` keeps type descriptions within 160 characters; `pageMeta` drops the " — silentship" suffix past 65 characters; rollout titles are `Office.js <build> (<channel>): N API changes` with "N API changes in X of Y host files"; a single notable change is named by its path (`latestNotableChange` returns `path`); shorter home and note texts; `/notes` `lastmod` takes `updated`.

### [Feature] SEO: stable h1 keywords, own link previews, structured-data images

- **Files:** `frontend/components/Headline.js`, `frontend/components/ChannelStatus.js`, `frontend/app/globals.css`, `frontend/lib/ogCard.js`, `frontend/app/opengraph-image.js`, `frontend/app/notes/[slug]/opengraph-image.js`, `frontend/app/rollouts/[channel]/[group]/opengraph-image.js`, `frontend/app/reference/[type]/opengraph-image.js`, `frontend/lib/jsonLd.js`, `frontend/next.config.mjs`
- **Why:** the home h1 changed with every build and never said "Office.js changelog"; the rollout h1 was a bare build number; rollout and type pages shared one generic preview; `TechArticle` had no image; no HSTS.
- **What:** the home eyebrow "Office.js changelog · <state>" sits inside the h1; rollout h1 "Office.js <build>"; a hidden h2 for the live status section; per-rollout and per-type previews on one shared design (`ogCard`), long API paths wrap after a dot; `TechArticle` always has an `image`, the publisher a `logo`; `Strict-Transport-Security: max-age=31536000`.
