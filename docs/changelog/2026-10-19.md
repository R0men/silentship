# 2026-10-19

### [Feature] OneCDN endpoint: two more channels

- **Files:** `backend/src/config.js`, `backend/src/pipeline/run.js`, `backend/src/pipeline/rollouts.js`, `backend/src/cli.js`, `.env.example`, `docs/SETUP.md`, `docs/architecture/crawler.md`, `docs/architecture/rollouts.md`, `docs/architecture/cdn-facts.md`, `TECH.md`
- **Why:** since 2026-09-25 Microsoft's docs call `appsforoffice.microsoft.com` legacy and recommend `officeapis.public.onecdn.static.microsoft/{1,beta}/`. Add-ins on the new address load every host file from there, so it has to be watched too.
- **What:** channels `onecdn-prod` and `onecdn-beta` with the same sampling (8 samples on fresh connections, conditional requests), crawled after the legacy ones; `LEGACY_CHANNEL` pairs them. Each run logs its duration (`runs.durationMs`); a full crawl longer than 10 minutes is logged as a warning. A channel's first run (`bootstrap`: no file has a state yet) records the newest version of every file as stable and creates no rollouts, so a new channel starts without phantom releases; a channel with a stable version is never re-baselined, also after a restart. Measured: 5–9 s per channel, both endpoints serve byte-identical host files on build 16.0.20606.15070.

### [Feature] Loader security-default flags and the `loader-flags-changed` event

- **Files:** `backend/src/crawler/loader.js`, `backend/src/pipeline/run.js`, `backend/src/notify/alerts.js`, `backend/src/notify/email-templates.js`, `backend/src/analysis/reclassify.js`, `docs/architecture/alerts.md`, `docs/architecture/api-surface.md`, `docs/architecture/data.md`
- **Why:** the OneCDN `office.js` is the legacy one plus `isOsfSecurityDefaultsEnabled = true; osfLoadMsAjax = false;` — Trusted Types on, MicrosoftAjax not loaded. If the legacy endpoint adopts these flags, add-ins that rely on `Sys.*` / `Type.registerNamespace` break edge by edge.
- **What:** every loader's flags are read (top-level literal assignments only, also minified `!0`/`!1`; `null` when unset) and stored with the stable loader (`fileStates.stableFlags`) and each new loader version (`rollouts.fromFlags/toFlags`), with `bodyHashSansFlags` to compare endpoints. A changed flag makes the rollout High (`flagsChanged`), confirmed like any group, alerted to every subscriber — also inside a build that was alerted on before — with the notice and a link to Microsoft's CDN page. Checked on the real files: legacy `null/null`, OneCDN `true/false`, hashes without the flags equal.

### [Feature] One alert per build across both endpoints

- **Files:** `backend/src/notify/alerts.js`, `backend/src/notify/email-templates.js`, `docs/architecture/alerts.md`
- **Why:** host files are identical on both endpoints, so every build is a group on each and would alert twice.
- **What:** email and Slack go out from legacy channels; a OneCDN channel alerts only for `loader-flags-changed` or a build legacy has not shown, to the subscribers of its legacy channel. Alert links go to the track's page.

- **What:** releases (`listReleases`, `getRelease`, `sitemapReleases`) — one per track (production, beta) and build with both endpoints; numbers from legacy, `diverged` when the build is on one endpoint only, a host file differs, or the loader flags changed. Two cards with "Same build on legacy and onecdn" or each endpoint's build; one list row per build with an endpoint badge only on divergence; the rollout page has a progress bar per endpoint, "Host files byte-identical on both endpoints" or the files that differ, and the flags notice only when they changed. `/rollouts/onecdn-*/…` redirects (301) to the track's page; sitemap and RSS list each release once. `/reference` follows the legacy channels only.

### [Bug Fix] "Rollouts" in the nav did nothing on a second click

- **Files:** `frontend/components/SectionLink.js`, `frontend/app/layout.js`, `docs/architecture/frontend.md`
- **Why:** the nav link was a next/link to `/#rollouts`; once the URL already had that hash, a second click (after scrolling back up) was a navigation to the same URL and did not scroll.
