### [Feature] Sign-in to alert settings by email code; the browser remembers the subscriber

- **Files:** `backend/src/web/server.js`, `backend/src/notify/email-templates.js`, `backend/src/notify/alerts.js`, `backend/src/cli.js`, `frontend/components/SignIn.js`, `frontend/components/Settings.js`, `frontend/components/Subscribe.js`, `frontend/lib/account.js`, `frontend/app/layout.js`, `frontend/app/settings/page.js`, `frontend/app/privacy/page.js`, `frontend/app/globals.css`, `backend/test/delivery.test.js`, `TECH.md`, `docs/architecture/alerts.md`, `docs/architecture/web.md`, `docs/architecture/frontend.md`
- **Why:** the settings were reachable only from the link in an email, so most subscribers would never learn they exist.
- **What:** confirming a subscription opens `/settings` with "You're subscribed" instead of the home page. "Alerts" in the nav and "Manage your alerts" under the subscribe form open `/settings`; without a remembered token it asks for the email: a subscribed address gets a 6-digit code and a "Manage alerts" button (`POST /api/signin`, `/api/signin/verify`; code hashed, 15 minutes, 5 guesses, used once; the subscribe form's email limits), any other address gets the confirmation email; the reply is the same either way. The token is kept in localStorage and removed from the address bar; "Forget this browser" clears it, and a token the API refuses is forgotten. A remembered subscriber sees their address instead of the subscribe form. `/privacy` mentions the local storage; `mail-preview` includes the sign-in email.

### [Feature] Public read-only API `/api/v1` with documentation at `/developers`

- **Files:** `backend/src/web/public-api.js`, `backend/src/web/server.js`, `backend/test/public-api.test.js`, `backend/test/delivery.test.js`, `frontend/app/developers/page.js`, `frontend/app/layout.js`, `frontend/app/globals.css`, `frontend/app/sitemap.js`, `frontend/app/llms.txt/route.js`, `README.md`, `TECH.md`, `docs/architecture/web.md`, `docs/architecture/frontend.md`, `docs/architecture/seo.md`, `docs/architecture/README.md`
- **Why:** the data was reachable only through the site's internal `/api/*`, whose shapes change with the pages; integrations (dashboards, bots, add-ins) need a format that does not break.
- **What:** `/api/v1/releases`, `/releases/{track}/{build}`, `/types`, `/types/{type}` in shapes of their own (named fields only, nothing internal); v1 only gains fields, a breaking change would be `/api/v2`. CORS `*` on this prefix only and never with credentials (`/api/settings` and sign-in send none, tested); 60 requests per minute per IPv4 address or IPv6 /64 and 1 200 per minute overall, `RateLimit-*` and `Retry-After` headers; every parameter validated, fixed error codes, `nosniff` and a `default-src 'none'` CSP; a cache of its own, uncached paging cursors, unknown types answered without a database query. `/developers` documents it; "API" replaces "RSS" in the nav, RSS moves to the footer; sitemap and `llms.txt` list it.

### [Infra] The frontend listens on 127.0.0.1 only

- **Files:** `frontend/package.json`
- **Why:** the per-IP limits trust the address nginx forwards; a Next.js server reachable directly could be sent a forged one. The firewall already closes the port, this no longer depends on it alone.
- **What:** `next start -H 127.0.0.1 -p 3000`, like the backend.
